# `data/catalogs/` — one directory per GOÄ edition

A fee schedule is not a constant. An invoice written in 2019 was written under the 2019 catalog and
has to be audited against that one; auditing it against today's produces the right arithmetic on
the wrong law. So the engine does not load "the catalog" — it loads a **catalog edition**, named by
the directory it lives in:

```python
from app.catalog import load_catalog

load_catalog()                                     # DEFAULT_CATALOG_VERSION (goae_current)
load_catalog(catalog_version="goae_1996")          # data/catalogs/goae_1996/
```

Routing is a validated directory-name join and nothing more —
`app/catalog/catalog_loader.py::resolve_catalog_dir`. An unknown edition raises
`CatalogNotFoundError` listing the editions that exist; it never falls back to the default.

Every edition holds the same two files:

| file | what it is |
| --- | --- |
| `goae.official.json` | the positions, the Punktwert, the § 5 factor bands, and the edition's declared `catalog_version` |
| `overrides.json` | manual corrections, each with a reason, a source and a verification date |

## What is real and what is not

| edition | positions | data |
| --- | --- | --- |
| `goae_current` | 2192 | **Real.** The official consolidated GOÄ, imported from gesetze-im-internet.de, SHA-256 of the raw download recorded in `source.sha256_raw` and matched against `data/raw/manifest.json`. This is the only edition that may price a real invoice, and it is the default. |
| `goae_1996` | 40 | Synthetic fixture. |
| `goae_2012` | 41 | Synthetic fixture. |
| `goae_2026_current` | 42 | Synthetic fixture. |
| `goae_neu_draft` | 42 | Synthetic fixture. |

The four fixtures exist to prove that routing works, not to describe any historical fee schedule.
They are generated by `apps/engine/scripts/make_temporal_fixtures.py`, each declares
`"synthetic": true`, each position carries `provenance: "illustrative"`, and loading one logs a
warning naming the edition. Their Ziffer texts are borrowed from the real snapshot so they read
like a fee schedule; **their Punktzahlen are fabricated and must never be quoted as GOÄ values.**

Regenerate them after changing the generator; CI can assert they are current:

```sh
cd apps/engine
python scripts/make_temporal_fixtures.py            # rewrite
python scripts/make_temporal_fixtures.py --check    # fail if the committed files drifted
```

The differences between the fixtures are the whole content of
`apps/engine/tests/test_multi_catalog.py`:

| | Ziffer 5 | Ziffer 20 | novel position |
| --- | --- | --- | --- |
| `goae_1996` | 100 Punkte | absent | — |
| `goae_2012` | 125 Punkte | present | — |
| `goae_2026_current` | 150 Punkte | present | `99` |
| `goae_neu_draft` | 150 Punkte | present | `999` (the same position, renumbered) |

"Base rate" is carried as Punkte because that is what a GOÄ catalog carries: money is
`Punkte × Punktwert × Steigerungsfaktor` (§ 5 Abs. 1 GOÄ), and there is no per-position euro
column to vary. The Punktwert stays at the statutory 5.82873 cent in every edition, because it
genuinely has not moved since 1996.

## Adding a real edition

1. Create `data/catalogs/goae_<year>/` and put a `goae.official.json` in it with the same shape as
   `goae_current`'s — including `source` provenance and a `catalog_version` no other edition
   declares. Do **not** set `"synthetic": true`.
2. Add an `overrides.json`, even an empty one.
3. Route to it: `load_catalog(catalog_version="goae_<year>")`, or make it the process default with
   `DEFAULT_CATALOG_VERSION=goae_<year>`.

The declared `catalog_version` and the file's SHA-256 both feed the receipt hash
(`app/services/receipt.py`), so two editions that declared the same version string would let one
receipt describe two different fee schedules. `tests/test_multi_catalog.py` fails if any two
shipped editions collide on either.
